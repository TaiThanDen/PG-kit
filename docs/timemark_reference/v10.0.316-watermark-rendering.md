Target: the LG-installed Timemark v10.0.316 APK, SHA-256
`b59c50b6c84ccfa180f8648bc6864a83040b61ff6fcd70eb7e092321042a1a98`.

REA establishes that `StrokeTextView.g` configures a separate stroked TextView,
and `onDraw` draws that view before the foreground. The production 1034 layout
declares a 0.5 dp stroke in 50% black. Its smaller text uses `waterMarkText`,
with 40% black shadow, radius 3.5 px and y offset 1.5 px.

`c60.t4.w` selects the watermark view and `framework.util.n.s/d` draws it onto
an ARGB bitmap using a scaled Canvas. It does not replace its text with a

## Implementation

Basic template 34 now uses `TimeLocationWatermark` for the JPEG content. The
native dp rounding is captured from display metrics; the output bitmap's short
side determines the export scale. No PreviewView dimensions or crop enter the
JPEG renderer. The clock's black stroke and the smaller text's shadows are
therefore preserved at output scale. The Sunday label matches `Chủ nhật`.
Basic template color, size and location switches use this path as well.

The exported address column, small horizontal inset and lower-right logo scale
are calibrated from the retained LG samples. They are empirical corrections,
not a claim that all remote settings, templates or device densities have been
recovered. The preview path retains its previously verified layout.

## Verification

`SavedWatermarkInstrumentation` is debug-only. It renders fixed reference input
through production code on LG, with black, white and transparent backgrounds.
The white-background assertion fails if the clock no longer leaves visible
outline pixels. The original renderer produced zero such pixels; the updated
renderer produced 2054 in the retained 2048 × 1536 test region. The release
merged manifest contains no instrumentation entry.

For the retained 09:23 landscape reference, `compare_saved_watermark.py`
compares solid foreground with no alignment or resizing:

This measures one matched-input raster state. Camera background, JPEG encoding,

Build debug and existing unit tests passed. Ignored evidence is under

### Intermediate bitmap diagnostic

The debug instrumentation also tests an alternative hypothesis: draw the
watermark at native display short-side resolution, then enlarge that cached
layer with bitmap filtering. This mode is diagnostic only; it does not change
production rendering. Against the same retained 09:23 fixture, its clock/date/
weekday/address foreground IoUs were 0.9195/0.6289/0.7103/0.7695, compared with
the production path's 0.9436/0.6591/0.7870/0.7421. Thus this simple resampling
model does not explain the residual differences well enough to replace the
current renderer. Both modes retain visible outline pixels on white; the
production clock assertion still passes. These are bounded raster observations,
not evidence that the reference uses either exact implementation.

The diagnostic fixtures and metric JSON are ignored under
`reference_app/v10.0.316/pixel/raster-diagnostic/`. Debug build and existing unit
tests passed again. A full-worktree whitespace check still reports pre-existing
CRLF whitespace in unrelated evidence files and `gradlew.bat`; the changed
instrumentation and this document pass the scoped check.

The debug-only `NativeTextWatermarkProbe` constructs ordinary TextViews to

and weekday, so it has not replaced production rendering. Neither probe
proves exact GL texture composition. Inputs for hour, minute, address and
location visibility are confined to debug instrumentation; the normal app
still takes real device time at shutter press.

## Missing address behavior

The fresh reference captures show an empty address field when Timemark reports
location failure. PG-kit previously placed the GPS coordinate fallback in that
field, adding a line and raising the header. It now keeps GPS data in the
coordinate field through `onLocationFix`, and updates the address field only
after reverse geocoding returns an address. The initial watermark address is
empty. Missing address input no longer reserves a blank location line in
template 34, in preview or JPEG. The capture snapshot preserves that empty
value instead of inserting an error message into the photo.

The debug raster check asserts that null, empty and whitespace-only addresses
produce exactly the same saved bitmap as disabling the template's address
field. This passed on LG along with the white-background outline assertion,
debug build and unit tests. A real camera pair at 15:32:59 and 15:33:13 confirms
that both apps omit the address and place the header at the bottom; evidence
is ignored under `qa/location-parity-current-hold/`. It is a current-hold save
check, not a fresh physical-orientation assertion. The pair crosses a minute
boundary and resolutions still differ, so it is not a pixel-parity result.

The source of a postal address may differ between Timemark's service and the
Android geocoder. No claim is made that their successful address strings match.
